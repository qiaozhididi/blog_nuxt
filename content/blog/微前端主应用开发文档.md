# 微前端主应用开发文档

本系统是企业 G3 应用矩阵的**微前端主应用（基座/容器）**，基于 **umi 3 + qiankun** 承载研发、业务、采购、库存、检测、设置等多个独立子应用，提供统一的布局、导航、登录态、权限与国际化能力。Ant Design Pro 5.2 脚手架，React 17 + antd 4 技术栈，源码约 380 个文件。

## 微前端架构设计

### 主子应用集成（qiankun）

- **注册**：主应用在 qiankun 配置中声明子应用名称与入口（开发环境指向子应用本地端口如 `localhost:9001`，生产环境为相对路径 `/<app>/`）；
- **装载**：路由配置中通过 `microApp` 字段将路径前缀与子应用绑定，访问对应路由时 qiankun 自动拉取并挂载子应用；
- **环境区分**：通过环境变量切换 entry，开发期主子应用各自独立 dev server 并行调试，生产期统一部署在 Nginx 下按路径分发；
- **环境判断**：子应用内通过 `window.__POWERED_BY_QIANKUN__` 判断是否运行在微前端容器中，可兼容独立运行与嵌入运行两种模式。

### 路由跳转规范

微前端下路由是常见踩坑点，团队沉淀了明确规范（写入 README 作为开发约定）：

- **应用内跳转**：标准 `history.push('/path')`；
- **跨应用跳转**：封装 `microAppPush(子应用名, 路径, state)` 公共方法，query 参数需手工拼接到路径后；
- **跨应用链接**：封装 `<CustomMicroAppLink>` 组件替代 umi `<Link>`（Link 不支持跨应用）；
- **新窗口打开**：封装 `getMicroLink()` 生成完整微前端路径，替代裸 `<a href>` 与 `window.open`；
- **限制说明**：跨应用跳转不支持 umi `location` 根属性传参，需改为 query 或 state 传递。

这些封装把 qiankun 的路由差异收敛为统一 API，业务开发者无需关心底层机制。

### 主子应用数据通信

- **initialState 同步**：主应用的全局 `initialState`（当前用户、权限、全局配置）通过 qiankun 自动同步到所有子应用，子应用沿用 `useModel('@@initialState')` 即可读取，无感知；
- **全局配置下发**：构建时通过 `define` 注入 API 网关地址、文件服务地址、全局业务配置（如样品材料仓库 ID）等，子应用共享同一份环境配置。

### 部署形态

主子应用构建产物**平级**放置于同一 Nginx 的 html 目录，通过路径前缀路由：主应用挂在根路径，子应用挂在各自前缀。HTML 响应设置 `Cache-Control: no-cache` 头避免版本缓存问题（微前端多应用独立发版的常见痛点）。

## 工程化设计

### 多环境构建

通过 `UMI_ENV` 区分 dev / sit / pre / uat 四套环境，对应独立的 config 文件与构建脚本（`build:dev`、`build:sit`…），构建产物目录独立命名。环境差异（API 地址、文件服务密钥）在 config 中声明，通过 webpack `define` 注入为编译期常量。

### 接口层组织

services 目录按后端服务域组织 API 封装（75 个文件），配合 `@umijs/plugin-openapi` 可从后端 Swagger 文档自动生成 TypeScript 接口与请求函数，减少手写样板代码，接口契约与后端保持一致。

### 国际化

168 个 locale 文件按页面/模块拆分词条，构建期按需加载；配合 `pro i18n-remove` 工具可一键清理伪国际化硬编码中文。

### 测试

- **单元测试**：Jest，针对工具函数与组件逻辑；
- **E2E 测试**：Playwright，覆盖关键业务链路（登录、主子应用跳转）；
- **提交钩子**：yorkie + lint-staged，提交前强制跑 eslint / stylelint / prettier，保证代码风格统一。

### 性能优化

- esbuild 替代 babel 做压缩与转译，大幅缩短构建时间；
- 路由级代码分割（umi 默认）+ 子应用按需加载，首屏只加载主应用；
- localforage 做大数据量本地缓存（如报表配置），减少重复请求。
